OAuth 2.0 Security Best Practices 2024

Published: November 14, 2024 | By: Alex Chen, Senior Security Engineer | Reading time: 8 min

OAuth 2.0 remains the industry standard for authorization, but implementing it securely requires careful attention to detail. This comprehensive guide covers the latest best practices for 2024.

1. Always Use PKCE (Proof Key for Code Exchange)

PKCE is now recommended for all OAuth flows, not just mobile apps. It prevents authorization code interception attacks.

// Generate code verifier
const codeVerifier = generateRandomString(128);
const codeChallenge = base64URLEncode(sha256(codeVerifier));

// Authorization request
const authUrl = `https://auth.example.com/authorize?
  client_id=${clientId}&
  redirect_uri=${redirectUri}&
  code_challenge=${codeChallenge}&
  code_challenge_method=S256`;

2. Implement Proper Token Storage

⚠️ Warning: Never store tokens in localStorage or sessionStorage for web applications. These are vulnerable to XSS attacks.

Use HTTP-only cookies with the Secure and SameSite flags:

// Server-side token storage
res.cookie('access_token', token, {
  httpOnly: true,
  secure: true,
  sameSite: 'strict',
  maxAge: 3600000 // 1 hour
});

3. Token Validation and Rotation

Always validate tokens on the server side and implement proper rotation:

async function validateAndRotateToken(accessToken, refreshToken) {
  // Validate access token
  const decoded = jwt.verify(accessToken, publicKey);

  // Check expiration
  if (decoded.exp < Date.now() / 1000) {
    // Rotate using refresh token
    const newTokens = await refreshAccessToken(refreshToken);
    return newTokens;
  }

  return { accessToken, refreshToken };
}
💡 Pro Tip: Use short-lived access tokens (15 minutes or less) and longer-lived refresh tokens stored securely.

4. Implement State Parameter for CSRF Protection

The state parameter prevents CSRF attacks during the OAuth flow:

// Generate random state
const state = generateRandomString(32);
sessionStorage.setItem('oauth_state', state);

// Include in authorization URL
const authUrl = `https://auth.example.com/authorize?
  client_id=${clientId}&
  state=${state}&
  redirect_uri=${redirectUri}`;

5. Scope Management

Request only the minimum necessary scopes for your application:

// Good: Minimal scopes
const scopes = ['read:user', 'read:email'];

// Bad: Excessive scopes
const scopes = ['read:user', 'write:user', 'admin', 'delete:everything'];

6. Redirect URI Validation

Always validate redirect URIs on your authorization server:

// Whitelist allowed redirect URIs
const allowedRedirects = [
  'https://app.example.com/callback',
  'https://app.example.com/oauth/callback'
];

if (!allowedRedirects.includes(requestedRedirectUri)) {
  throw new Error('Invalid redirect URI');
}

Conclusion

Implementing OAuth 2.0 securely requires attention to multiple layers of defense. By following these best practices, you can significantly reduce the risk of authentication vulnerabilities in your applications.
